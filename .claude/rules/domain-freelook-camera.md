# Mouse Look, camera and CVars

- **CVarManager** — all addon `SetCVar` writes; prior snapshot capture/restore; reticle presets + overrides; Interaction HUD SoftTarget subset (never writes SoftTargetIconInteract/GameObject); Mouse Look camera (`ApplyMouseLookCamera` / `ClearMouseLookCamera`; shoulder tweens with vignette duration — intent vs blend; `shoulderFollowsMouseLook` gates chrome-linked ease vs constant offset; DynamicCam: unlock→0 + optional restore from live/snapshot, else relinquish; `SetDynamicPitch` sticky; `ApplyActionCamMotionSicknessGate` / `respectMotionSickness`); `SyncTargetFocusFromFocusUnit` kept even with DynamicCam; `MigrateMouseLookCameraDB`. `ConfigStickyCrosshair` is an uninstall helper only. `BeginCameraSpeedDip` / `EndCameraSpeedDip` own the cursor-centering speed dip: the prior snapshot is taken before the dip writes, the saved speeds live in CVarManager (no per-lock allocation), and while a dip is pending `CM.SetCVar` on `cameraYaw/PitchMoveSpeed` updates the value to restore instead of writing (so `SetMouseLookSpeed` / the speed slider in that frame are not undone); `RestorePriorCVars` cancels a pending dip.
- **Minimum Zoom** — `global.minCameraZoom` (0 = off), `CM.ApplyMinCameraZoom` in CVarManager: no CVar exists and the mouse wheel zooms through the engine binding (a `hooksecurefunc("CameraZoomIn")` never fires), so the `CAMERAZOOMIN` keys get a `SetOverrideBindingClick` to a plain button that zooms by `min(1, distance - min)` (own target tracked for 0.3 s because `GetCameraZoom` lags), queued via `TryApplyBindingChange` and re-applied on `UPDATE_BINDINGS`. A 0.03 s throttled OnUpdate frame (shown only while the option is on) is only the safety net for zoom the keys didn't cause. Always active, even with DynamicCam / SteadyCam.
- **FreeLookController** — mouselook lock/unlock; cursor centering (issue 189) is a one-frame bounce when the crosshair is on: `CM.BeginCameraSpeedDip(0.1)` → centering `1` → `MouselookStart` → `MouselookStop` → centering `0` → `MouselookStart`, then `CM.EndCameraSpeedDip` on the next frame through one shared callback (the engine applies the centering warp as a Mouse Look turn scaled by `cameraYaw/PitchMoveSpeed`; `0` is rejected, `0.1` is the floor on 12.x; if Begin returns false the client rejected the dip and the lock is a plain start). OPie rematch latch; sheath debounce; Apply/Clear Mouse Look camera on lock / permanent unlock.
  Force lock (non-Once) ignores the Mouse Look keybind and clears a stale `FreeLookOverride`; the tap poll never clears chrome / sheathes while mouselooking.
- **Tooltip modifier** — `global.hideTooltip` hides `GameTooltip` while Mouse Look is on; `global.tooltipModifier` (ALT default | CTRL | SHIFT) lets the held key through (`CM.IsTooltipModifierDown`). `MODIFIER_STATE_CHANGED` + `UPDATE_MOUSEOVER_UNIT` (`TOOLTIP_MODIFIER_EVENTS`) → `CM.OnTooltipModifierChanged` rebuilds the player's own `GameTooltip` for the mouseover unit, pinned beside the crosshair, and hides it on release. The game re-anchors a tooltip it shows for a new unit to the cursor every frame (no `SetPoint` survives), so after a swap the tooltip is zeroed in alpha, hidden and rebuilt through `GameTooltip_SetDefaultAnchor` from its `OnUpdate`, then faded in; `IsTooltipPinned` compares offsets with a tolerance (scale makes them inexact). Never replace the tooltip with a custom frame: players' tooltip addons restyle `GameTooltip`.
- **Vignette** — edge darkening, smooth fade. `global.vignetteConditions` is a CSV string (`mouselook` | `combat` | `interaction`; empty = off; a string because `MergeDefaults` grafts default keys onto saved tables) combined by `global.vignetteMatch` (`any` | `all`). Mouse Look = `CM.IsMouseLookCameraChromeActive`, combat = `UnitAffectingCombat("player")`, interaction = open NPC windows tracked from `PLAYER_INTERACTION_MANAGER_FRAME_SHOW/HIDE` (`VIGNETTE_INTERACTION_EVENTS` → `CM.OnVignetteInteractionEvent`, a set keyed by interaction type). Options on the Mouse Look tab: a `ctx:Dropdown{multi = true}` checklist (`isOn`/`toggle`/`summary`) plus a match dropdown; the old `vignette` boolean migrates in `InitDatabase`. **Support Mode tint** (`CM.RefreshVignetteTint`; `char.supportModeTintVignette`, toggle on the Support Mode tab): the vignette art is black (RGB 0, the shape is in the alpha), and a vertex color multiplies the texture's color, so it can't be tinted. A white copy with the same alpha (`Assets/ui/vignette-tint.tga` = `CM.Constants.VignetteTint`, built by `scripts/art/make-vignette-tint.py`, rerun only if the atlas is exported again) sits one sublevel above it with the `support` crosshair reaction color as vertex color; `tintBlend` (0 = dark, 1 = tinted) eases toward the target in the vignette's own OnUpdate and splits the one vignette alpha between the two textures. So the tint has no conditions of its own: it shows exactly when the vignette does, and never when the vignette is off. A separate screen-edge glow with its own toggle was built first and dropped on review for that reason.
- Camera Features (Motion Sickness Protection, Dynamic Pitch, Pitch Strength, Shoulder Offset) live on the General tab below Mouse Look (no Camera tab).
- **AutoCursorUnlock** — answers "should the cursor stay unlocked": watched frames (`FramesToCheck` + watchlist + wildcard tracking when `DB.global.frameWatching`, incl. OPie), vendor mounts, pet battle, feign death, and the user's `customCondition`; `customLockCondition` is the inverse (force Mouse Look on), both via `Core/Runtime/UserLuaCondition.lua`. It only answers; `FreeLookController` owns lock/unlock and the `ShouldFreeLookBeOff` aggregation. OPie visibility notifies FreeLookController so centering rematches after the ring closes. `CM.CloseUnlockWindows` (out of combat: `CloseAllWindows`, `CloseAllBags`; in combat the UI panels and bag frames are hidden one by one and protected ones skipped; plus Blizzard menus and non-protected watched frames; OPie untouched) backs `global.closeWindowsOnMouseLook` (General tab "Close Windows"): the Mouse Look key press while one of those windows keeps the cursor free closes them and reconciles Mouse Look at once. Frame lists/mounts live in `Constants/FrameWatch.lua`.

**In-game checks:** ground-targeted spells free the cursor at once and re-lock on place / cancel; rapid Mouse Look toggles don't flash sheath / unsheath; Force Lock / Force Unlock with `return true`: Lock Once / Unlock Once fire on the first check only, until the snippet turns false and true again, and Force Lock wins over Force Unlock; opening bags or ground targeting still unlocks. Close Windows on: the Mouse Look key closes bags / character panel / vendor / a context menu and re-locks, in combat unprotected windows close and no ADDON_ACTION_BLOCKED appears, off = unchanged. Vignette Shows When: Any / All across Mouse Look, combat, NPC windows; `/reload` with a window open starts clear.

## FreeLookController.lua notes

- SheathWeaponsWithMouselook: unsheath on intentional Mouse Look; sheath on tap unlock (poll detects binding release) and Auto Cursor Unlock. Hold never sheaths. Ground targeting and OPie keep weapons drawn. Sheath requests are debounced (~1.5s) so rapid Mouse Look toggle does not flash sheath/unsheath; unsheath and re-lock cancel any pending sheath.
- OPie: when a ring is visible, unlock path may free centering; Rematch after the ring closes re-bounces freelook if still desired.
