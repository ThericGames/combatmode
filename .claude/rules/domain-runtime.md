# Runtime shell, events and constants

- **Runtime.lua** — `local addonName, CM = ...`; lifecycle (`ADDON_LOADED` / `PLAYER_LOGIN` → `OnInitialize` / `OnEnable`), slash `/acm` `/actioncombatmode`, throttled `CombatMode_OnUpdate` (`ReconcileFreeLook` + crosshair reaction), welcome/changelog scheduling, `UninstallCombatMode` (restores `priorCVarSnapshot` and BUTTON1/2 camera binds, then `ReloadUI`). `GetBindingsLocation` → `"global"` vs `"char"` from `useGlobalBindings`. `CM.ApplyOutlineSlug(label, font?, size?)` is the one shared HUD text look (outline + slug, smooth scaling, 0.5 shadow at 1,-1; matches `UI.ApplyOutlineFont` in the UI addon): Assist HUD, Ally Cycle HUD and the radial menu all use it, so change the look there only.
- **Safe.lua** — `CM.Safe`: `IsSecret`, `PublicBool` (public booleans only), `PublicTruthy` (any public non-nil value, for APIs answering `1`/`nil` on older clients), `PublicNumber`. Loads right after Runtime.lua. Modules alias these and never redefine them; see `lua-safety.md`.
- **InitDatabase** merges `Constants.DatabaseDefaults` into `global` + `char["Name - Realm"]`, then coerces Forever's `1`/`0` to booleans (`CM.DbBool` / `NormalizeBools`). **Every data-shape change (rename, removed feature, reshaped table) is an explicit, commented migration here**, never in a feature module. Existing ones drop `partyRadial`, convert `reticleHideSoftIndicator` → `selectionCircleMode` and `assistedHighlightEnabled` → `assistedHighlightMode`, drop the merged `interactionHUD*` keys, move an Ally HUD `allyCycle.hudSide` of LEFT / RIGHT to BOTTOM, disable click-cast slots using removed Toggle Focus actions, and rewrite the old situational default.
- **EventRouter.lua** — `eventCategoryMap` is built from `Constants.BLIZZARD_EVENTS`; `CombatMode_OnEvent(self, event, ...)` dispatches by category (one event may be in several). `REFRESH_BINDINGS_EVENTS` are coalesced through `C_Timer` so bursts run one `RefreshClickCastMacros`; self-echo events during apply are suppressed. A new event = add to a `BLIZZARD_EVENTS` category in `Constants/Gameplay.lua` + a handler in `EventRouter`; it never registers events itself.
- **BindingQueue.lua** — `TryApplyBindingChange(context, applyFn)` runs now out of combat, else queues; `FlushDeferredBindingChanges` (on `PLAYER_REGEN_ENABLED`) pcalls each closure. Callers pass closures; it doesn't build macros or bindings itself.
- **Bootstrap.lua** — ordered enable sequence (CVar snapshot, overrides, frame tracking, crosshair, legacy macro cleanup, MoveAndSteer → Mouse Look rebind, Ally Cycle init). `RemoveLegacyMacros` deletes old `CM_` macros that still hold our text and aren't on a bar, so never name addon-created macros `CM_*`.
- **UserLuaCondition.lua** — `CM.EvaluateUserLuaCondition(source, cache, label)` compiles user Lua with `loadstring` (cached per consumer; empty → false; errors logged throttled, return false). Used by Auto Unlock, Mouse Look force lock, crosshair situational texture. Treat the source as untrusted input: never pass secrets or write APIs into its environment.
- **Constants** — static data only (`Namespace.lua` first). `Gameplay.lua` holds `BLIZZARD_EVENTS`, `ClickCastBars` (ACTIONBUTTON + MULTIACTIONBAR1–7, MultiBar5–7 = 145/157/169 bases), `ActionsToProcess` / `OverrideActions` / `ButtonsToOverride`, and `ReticleTargetingBuiltinExcludeSpellIds` (skyriding). `DatabaseDefaults.lua` is the single place for defaults. Check `Constants/CVars.lua` + `Core/Runtime/CVarManager.lua` + the CVar editor data together when touching reticle CVars.
- `Embeds.xml` is the load order (and the root frame `OnEvent` / `OnUpdate`); `Bindings.xml` declares keybinds (names are internal "Combat Mode" IDs; the category label says "Action Combat Mode"). The TOC lists many client interface numbers; don't change them without being asked.

**In-game checks:** `/acm` and `/actioncombatmode` open options; keybinds survive `/reload` and disable / re-enable; binding writes in combat queue and apply on leaving combat; Uninstall restores the CVar snapshot and the left / right click camera binds, disables the addon and reloads; the changelog pops up once per version (`lastSeenChangelogVersion`).

## CVarManager.lua notes

- GetEffectiveReticleTargetingCVarValues = preset ∪ global.reticleTargetingCVarOverrides; global.reticleOutline == false swaps the outline CVars for Outline 0 + Blizzard's fades. ApplyReticleOutlineCVars writes just those (Target Outline toggle). global.selectionCircleMode (Selection Circle) drives ObjectSelectionCircle / UnitNameFocused (both hidden from the CVar editor): "target" = the circle while a hard target exists, "locked" = while it is also your focus (Target Lock), both only while SoftTargetMatchLocked is 1 (the soft target then sits on that target); "soft" = Blizzard's circle and name; "hidden" = none. ApplyReticleSelectionCircleCVars writes just those on option changes and PLAYER_TARGET_CHANGED / PLAYER_FOCUS_CHANGED; turning the circle on waits until the soft target is on the hard target so it never slides over.
- SoftTargetIconFriend/Interact/GameObject (InteractionHUDIconCVarNames) are in the effective preset only while the crosshair and the Interactable Indicator are on (an editor override still wins); SyncInteractionHUDIconCVars hides or restores them on toggles. A snapshot older than these CVars is backfilled before their first write (SetCVar).
- SetDynamicPitch — sticky with the option; strength is global.dynamicPitchStrength (ground pad). Flying pad is that value times Flying/Base so the air tilt stays proportional. ApplyActionCamMotionSicknessGate keeps CameraKeepCharacterCentered / CameraReduceUnexpectedMovement at 0 while pitch, autofocus, or owned shoulder needs ActionCam (not freelook alone — toggling MS with Mouse Look snaps skyriding FOV/zoom). Never re-enable MS while flying. global.respectMotionSickness (Motion Sickness Protection): restore MS from snapshot and suppress Dynamic Pitch / Shoulder Offset / Target Focus CVar writes (options stay saved; turning Protection off re-applies them).
- ApplyMinCameraZoom — global.minCameraZoom; no CVar exists and the mouse wheel bypasses the CameraZoomIn global, so the CAMERAZOOMIN keys get an override click (queued out of combat, re-applied on UPDATE_BINDINGS) that stops the zoom at the minimum; a small throttled OnUpdate (shown only while the option is on) catches zoom the keys didn't cause (off at 0; applies regardless of DynamicCam / SteadyCam).
- SwapShoulder — keybind: negates char.shoulderOffset (tweened), or the live CVar when DynamicCam / SteadyCam own it. Intent (slider / DC snapshot) is separate from the live blend. Optional global.shoulderFollowsMouseLook (default off): when on, ease with Mouse Look chrome; when off, keep configured offset always. DynamicCam + follow: drive only unlock→0 / restore; otherwise relinquish. Mid-tween toggles retarget; never treat a mid-blend CVar sample as intent.
- BeginCameraSpeedDip(speed) / EndCameraSpeedDip — FreeLook's centering bounce (issue 189): snapshot first, save cameraYaw/PitchMoveSpeed, write the floor; restore next frame. A same-frame re-lock keeps the first saved values; Begin returns false (speeds untouched) when the client rejects the value. While pending, CM.SetCVar on those two names updates the value to restore instead of writing. RestorePriorCVars cancels a pending dip.
