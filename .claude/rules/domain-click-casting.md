# Click casting and Reticle Targeting

- **BindingOverrides** — click-cast / Target Lock secure buttons; Cycle Lock Next/Previous as dedicated Bindings.xml keys (`ApplyCycleFocusBindings` + `SetOverrideBindingClick`; defaults Shift+mouse-wheel). Macro slots skip the reticle proxy (`CM.GetDisplayedActionSlotInfo`); Bonus/Override/TempShapeshift macros use `SetOverrideBindingClick` on the live frame. On the keyboard proxy path, a key whose bar can show a Party Wheel spell is bound to `CombatModePartyWheelKey` instead (`CM.PartyWheelPrepareKey(bindingIndex, bindingName, macroText)` returns the button + click arg; unlisted spells forward to a route button running the same click-cast macro).
- **PlayerMenu** (`Core/ClickCasting/PlayerMenu.lua`) — with Mouse Look on and the crosshair (`mouseover`, then `softinteract`; the first that exists decides) on another player, the Interact key opens that player's unit menu. `CombatModePlayerMenuButton` (`SecureUnitButtonTemplate`, `togglemenu`, kept shown 1x1 alpha 0, never hidden or the click does nothing; bound directly). Tried and dropped: opening via `UnitPopup_OpenMenu` from PostClick (taints the menu: raid markers throw `ADDON_ACTION_FORBIDDEN`), `TargetUnit` (protected), and calling `Click` from the restricted environment (no such method). The key is bound to `CombatModePlayerMenuHold` (`SecureActionButtonTemplate`, AnyDown+AnyUp, `useOnKeyDown=false`): PreClick stamps the press time, and on release sets `macrotext` to the armed macro only if the key was held `HOLD_SECONDS` (0.4), else empty (a short press does nothing; native interact can't be re-issued, `InteractUnit` is protected). Armed macro = `/click CombatModePlayerMenuButton`, prefixed with `/target <unit>` for a player with no stable token (not targeted, no nameplate). `CM.GetPlayerUnderCrosshair` is shared with the Interaction HUD's player prompt. `CombatModePlayerMenuBinder` (`SecureHandlerStateTemplate`, driver `[nocombat] on; off`, strings "on"/"off") bind the key with `SetBindingClick`, so combat drops it securely. `CM.UpdatePlayerMenu` runs from the `CombatMode_OnUpdate` tick and on `PLAYER_REGEN_ENABLED`; `CM.DisarmPlayerMenu` when Mouse Look is off. The `unit` attribute is a stable token (party/raid, nameplate, target) since the crosshair leaves the player once the cursor frees. A changed key needs the driver unregistered and re-registered (the snippet only runs on state change). Fails closed on secret values. Setting: `global.disablePlayerInteract` (General tab "Disable Player Interaction", default off, `CM.IsPlayerMenuEnabled` is its inverse); on = `UpdatePlayerMenu` only disarms, so the Interact key stays native (the override swallowed it on multi-passenger mounts). No nameplate anchoring.
- **ComposedMacros** (`Core/ClickCasting/ComposedMacros.lua`) — the "Reticle Targeting Macros" shelf, an option below the spell lists on the Reticle Targeting tab (`TabReticleTargeting.lua`, `CM.EnumerateComposedMacros`) lists macros that open with an ACM preline as round icons; drag/click calls `PickupMacro` (out of combat) so players drop them on action bars (they then follow bar swaps), and its trailing "+" opens `UI/Editors/ComposedMacroEditor.lua`. The editor writes a real WoW macro = `CM.GetActiveTargetingPreline()` + user body (255 cap, no `/click` reserve) and remembers the body in `global.composedMacros[name]`; `RebuildComposedMacros` (from `RefreshClickCastMacros`) re-edits those macros when the preline changes. The Run MACRO dropdown lists existing macros (icon + Reticle Targeting tag) and just stores `macroName`. Never name macros with a `CM_` prefix (`RemoveLegacyMacros` deletes them).
- **Nested macro /click:** SecureActionButton `macrotext` cannot `/click` another macro button (silent no-op). Classify bar slots with `CM.GetDisplayedActionSlotInfo` (live frame action; reject stale override 121–132 after dismount; else page/bonus or MultiBar slot) — not hard-coded slots 1–12. **255 cap is on executed text (tested in game):** `macrotext` set from a `SecureHandlerBaseTemplate` OnClick snippet (M6-style inlining) is cut at 255 exactly like plain `macrotext`, so inlining the preline + a bar macro's body cannot beat the limit; it would only add the preline to short plain macros (preline ~125 chars) and was dropped. **Visible-slot probe (tested, dropped):** a `SecureHandlerBaseTemplate` OnClick snippet can read the visible bar button's slot live in combat (`id + GetEffectiveAttribute("actionpage")*12 - 12`, else its `action` attribute) and `GetActionInfo` it; on default bars across druid form swaps it matched `CM.GetDisplayedActionSlotInfo` on every press, for keyboard keys and click-cast mouse buttons, and helpful/harmful targeting was identical in and out of combat. The reported "stuck on bar 1" bug did not reproduce on default bars; Bartender4/Dominos/ElvUI were untested. Needed from a reporter before reopening: bar addon + version, key or mouse button, what was swapped (form/page/stance), combat only or not, and the slot's spell or macro.
- **M6 macros in Run MACRO (tested, dropped):** an M6 stub (`_M6+sXX`) fails as `MACRO name` (macro running a macro) and as `CLICK M6Prime:sXX` too: M6Prime's click wrap checks `RW:IsPyrolysisActive()` and prints "Cannot execute an M6 macro now". M6 only runs macros through its own `M6Bind!b<actionId>` proxies, which exist only for macros with a bind set in M6, and mapping a stub to that id has no public API. Tell M6 users to use M6's own conditional binding.
- **Help/harm routing (TargetingMacroBuilder):** helpful + Ignore Friendlies → no `/tar` (not keys-gated; Forever / unbound); helpful + Any → `/tar` `[help]` mouseover / `@softinteract` / `@anyfriend` (hostiles do not steal a friendly hard target); harmful → enemy `/tar` when cycle keys bound (including solo); no last-ally retarget except optional restore-after-harm. Restore-after-harm: slim harm `/tar` (keeps `[@focus,harm]`) + `/targetlasttarget [harm]` (`IsAllyCycleRestoreAfterHarm`; healer spec default until toggled; skipped when Auto Target Lock is on).
- Standalone editor windows (`UI/Editors/*`) register in `Embeds.xml` after the `UI/Options` toolkit; keep `CM.Open*` combat-guarded where frames are created. When changing reticle CVar presets or exclusions, update `Constants/CVars.lua`, `UI/Editors/ReticleCVarEditorData.lua` and `Core/Runtime/CVarManager.lua` together.
- **TargetingMacroBuilder** — builds the macrotext injected into click-cast proxies: `CM.BuildClickCastMacroText(bindingValue)` (no-op when `reticleTargeting` is off), preline variants (any / enemy-only × plain / auto-lock) with user overrides from `global.targetingMacroPreline*Override` (edited in `UI/Editors/TargetingMacroPrelinesEditor.lua`, effective after reload), optional ally-restore post-line, `/click` bar button or `/cast [@cursor]` for ground spells, and the cast-at-cursor / exclude spell lists. Hard limit: **255 characters** (`SECURE_MACROTEXT_MAX`); long macros fall back to `SLIMMER_PRELINE` (matters for ElvUI/Bartender with key-down). Auto-lock prelines also re-sync `/focus` so a sticky empty focus can't leave a dead lock.
- **SupportMode** (`Core/ClickCasting/SupportMode.lua`, loads before BindingOverrides; options on `TabSupportMode.lua`) — the Support Mode key (`Combat Mode - Support Mode`; enabled = Reticle Targeting on + key bound, no master toggle). `CombatModeSupportMode` (`SecureHandlerBaseTemplate`) holds the state (`sm` 1 / 0) and frame refs `p1..p<smcount>` to every proxy with more than one macro text: the 8 `CombatModeClickCast*`, the 12 main-bar `CombatModeSlot*` and main-bar Party Wheel route buttons. Out of combat the owners store both texts (`CM.SetModeMacroText`: `sm-off` / `sm-on` attributes, `macrotext` = the one for the current mode); the key button `CombatModeSupportModeKey` (type macro, wrapped OnClick, `useOnKeyDown` always on: a toggle on the key press, the release is dropped) flips `sm`, copies the right text into every proxy and runs `/changeactionbar <page>` (enter) or `/changeactionbar 1` (leave) as its own macro, so the whole swap works in combat. A hold-to-stay-on Key Behavior option existed during development and was removed before release (the user's call: nobody would hold a key for this); `InitDatabase` drops its saved key.
  - **Macro texts** (`BuildModeMacroTexts` in BindingOverrides → `CM.BuildClickCastMacroText(binding, opts)`): `opts.page` classifies an ACTIONBUTTON by that page's slot instead of the displayed one (the bonus bar only applies on page 1, as in `ActionBarController_UpdateAll`); `opts.support` turns a **helpful** spell into the single line `/cast [@mouseover,help][@target,help] <spell name>` (`SupportCastLine`; Classic rank appended as `Name(Rank N)`): a true mouseover cast that never changes the hard target (asked for after testing: the target-then-click version hard-targeted the ally), else a cast on the friendly hard target (asked for so an **Ally Cycle** pick is healed when you aim at nobody; the crosshair wins when both exist, and any friendly hard target counts, since a macro can't tell who picked it). With neither one friendly every condition fails, so nothing is cast (never auto self-cast; `help` is true for a dead ally, so resurrections work). It is a named `/cast` because `/click` can't name a unit; the cost is that the spell is the one on the slot when the macro was built (out of combat), not the live slot, and the Ally HUD (hard friendly target only) doesn't show an ally healed by mouseover. The preline `/tar [@mouseover,help]` + `/stopmacro [nohelp]` + `/click` (`SupportModePreLine`; this one does change the target) remains only as the fallback when the spell name isn't available. Harmful spells, items and cast-at-cursor / excluded spells keep their normal route. Mouse click-cast buttons get the strict preline; keyboard main-bar keys only get the normal routing re-classified for the support page (other bars are not paged: one text). While the mode is on, the normal text is built with `page = 1`, because the displayed slot is the support page's.
  - **Self-cast** is a second key, `Combat Mode - Support Mode Self Cast` → `CombatModeSupportModeSelfKey` (wrapped OnClick, no action of its own): held = `smself` 1, and while the mode is on every proxy runs its third text `sm-self` (`opts.support = "self"`: for a helpful spell the single line `/cast [@player] <spell name>` (the same `SupportCastLine`), otherwise the same as `sm-on`). It is a named `/cast`, not `/tar player` + `/click`, because making yourself the hard target re-centred the shoulder-offset camera in game. `/tar player` + `/click` remains the fallback when the spell name isn't available. Only the 8 click-cast buttons have a self text. A modifier was tried first and dropped as the default: `[mod:shift]` in the preline clashes with the click binds, since SHIFT / CTRL / ALT + click are click-cast keys of their own (and on such a chord the condition is always true). It came back as the opt-in **Self-Cast Modifier** (`char.supportModeSelfCastModifier` "none" | "shift" | "ctrl" | "alt"; asked for with the condition that the option warns about the click binds it takes over), built from macro texts alone with no secure state: (1) the modifier's own chords (`SHIFT-BUTTON1` / `SHIFT-BUTTON2` for Shift) get the plain click's self-cast line as their `sm-on` / `sm-self` text (`ModifierSelfCastText` in BindingOverrides), so in Support Mode they self-cast the plain click's helpful spell instead of their own bind (slots 3 and 4 by default); when the plain click holds no helpful spell the chord keeps its own bind; (2) the plain clicks' `sm-on` text starts with `[mod:<it>,@player]` (`opts.selfMod`), for a chord with no click-cast bind of its own (disabled slot: the game falls back to the plain click's bind). A chord that doesn't run through a proxy (Run MACRO, a macro on its bar slot) can't be swapped and keeps running its macro. Keyboard keys are not affected. Leaving the mode resets `smself`, so a key release the client swallowed (`MouselookStop` sends spurious key-ups; Alt-Tab can eat one) can't stick past the mode; pressing the key again also clears it.
  - **What combat can't do:** which frame a key clicks (proxy vs the real bar button for macro slots, native binding for excluded spells) is decided out of combat from the displayed slot (`SetMouselookOverrideBinding` has no restricted-environment twin). A slot that is a macro on one page and a spell on the other is wrong until the next out-of-combat refresh (`ACTIONBAR_PAGE_CHANGED` triggers it at once out of combat). **Nameplates** are not on that list: `CM.SyncSupportModeNameplates` (CVarManager; `char.supportModeNameplateMode` from the **Nameplates** dropdown: `friendly` (default) = `nameplateShowEnemies` 0 + `nameplateShowFriendlyPlayers` 1, `all` = both 1, `none` = both 0, `keep` = untouched; `nameplateShowFriends` stands in on older Classic; the player's values wait in `global.supportModeSavedNameplates`, saved once per mode session so changing the dropdown while the mode is on keeps the first snapshot; the old Swap Nameplates boolean migrates in `InitDatabase`) writes the CVars from insecure code, in combat too. Checked in game: `select(6, C_CVar.GetCVarInfo(name))` (isSecure) is `false` for both, and the plates swap mid-combat. The code still reads that flag per CVar and, only where a client reports it protected, defers to `PLAYER_REGEN_ENABLED` (`CM.FlushSupportMode`) with the "Nameplates switch after combat" notice; don't describe the swap to players as out-of-combat only. (A secure-macro `/console` would not help there: it runs `forceinsecure()`.)
  - **Crosshair:** `OnModeChanged` calls `CM.RefreshCrosshairAppearance`; while the mode is on the idle reticle (state `base`, the Target Lock idle Dot) is tinted with the reaction color `support` (`CM.GetCrosshairIdleColorState` in Crosshair.lua; default cyan in `CrosshairReactionColors`, editable on the Support tab of the Reaction Colors editor; the Support Mode tab has no button for it, a duplicate was removed on review). That tint is easy to miss (reported after testing: the color changes with whatever is under the reticle), so the mode also has a shape: the **Support** card of the Crosshair Textures editor (`global.crosshairSupportId`, default `CrosshairSupportDefaultId` = `"Triangle"`, the Triangle preset's inactive texture (three chevrons; the user's pick after testing), `"none"` = off) replaces both the Inactive and the Active texture while the mode is on (`CM.GetCrosshairSupportTexturePath`, applied in Animations.lua), so the shape tells the mode and the reaction color still tells the target; scale animation and tints are the normal ones, and Mounted, Target Lock and the situational appearance keep their own textures. `OnModeChanged` also calls `CM.RefreshVignetteTint` (`Core/Vignette.lua`): with **Tint Vignette** on (`char.supportModeTintVignette`, default on) the Vignette cross-fades to the same `support` color. It is the vignette itself, not a second effect (changed on review), so it follows Vignette Shows When / Match and shows nothing when the Vignette is off; the Reaction Colors editor repaints it live.
  - **Reload:** the secure state starts off. `char.supportModeActive` marks a session that was on, so `CM.InitializeSupportMode` (Bootstrap, before the click-cast macros) pages back to 1 and the saved nameplate CVars are restored; Uninstall restores them through `RestorePriorCVars`.
- **AddonActionBarResolver** — maps ACTIONBUTTON / MULTIACTIONBAR1–7 to ElvUI / Bartender4 / Dominos button frames and forces `macroInjectionClickCastOnly` when those addons are loaded (caches cleared on binding refresh). It doesn't set bindings or build macro text.

## TargetingMacroBuilder.lua notes

- Auto-lock prelines: clear dead focus + dead hard target, /tar (soft ,nodead on focus/mouseover branches — harm alone matches corpses), then /focus resync ([nodead] any / [nodead,harm] enemy) so sticky empty-focus cannot leave a dead lock. Cleartarget prevents corpse re-lock on hard target.
- Helpful spells (Reticle Targeting): Ignore Friendlies → no /tar (keep friendly hard target). Any → /tar @mouseover if [help], then @softinteract (NPCs), then @anyfriend (players). A hostile under the reticle does not steal a friendly hard target. Not gated on Ally Cycle keybinds (Forever / unbound users). Unclassified + cycle keys bound → treated as help. Harmful + cycle keys → ENEMY / AUTO_LOCK_ENEMY (including solo). Auto-swing uses /startattack or /cast ! or /petattack after /tar. Restore `/targetlasttarget [harm]` is in-group only when cycle keys are bound (not Auto Lock). Its preline also clears a dead focus, falling back to a variant without that line when the whole macro would not fit in 255 (SLIMMER_PRELINE: ElvUI / Bartender with key-down).

## BindingOverrides.lua notes

- Clear Target / Clear Focus / Start Attack / Pet Attack / Toggle Focus run their CM.Constants.Macros text from the key's CombatModeClickCast proxy (CLICK binding), so no CM_ macros are created in the player's macro list. The Ping System actions (Ping, Attack, Warning, On My Way, Assist) and the raid markers do the same with CM.Constants.BlizzardActionMacros: they act on the unit under the crosshair (markers: the hard target first), only while Mouse Look is on. Auto Attack / Auto Shot / Shoot / Pet Attack bar slots use /startattack or /cast ! / /petattack after /tar so a swap cannot toggle the swing off.
- Keys whose bar slot can hold a Party Wheel spell click CombatModePartyWheelKey instead (CM.PartyWheelPrepareKey, Core/RadialMenu/PartyWheel.lua), which runs the same macro on a tap. Macro slots skip the proxy (nested macro /click is a no-op): native bind for ActionButton/MultiBar; SetOverrideBindingClick the live frame for Bonus / Override / TempShapeshift. Slot type from CM.GetDisplayedActionSlotInfo (paged / bonus aware; rejects stale override attrs after dismount).
