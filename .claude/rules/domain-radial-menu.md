# Radial Menu

Files in `Core/RadialMenu/`, in load order:

- `Data` — preset wheels (`CM.RadialPresetList`: Interface, Emotes, Misc; first-run seed, and `CM.RadialCreateWheel(at, presetKey)` adds one later, no key = blank; a preset entry is an action id or a list of ids for one slice, and `PresetWheel` drops what the client lacks, empty slices included, so Interface loses its Legacy slice outside Forever), `CM.RadialLayout` constants and the per-character wheel store (`char.radialMenu.wheels`, each `{name?, count, slots[1..8] = {kind = spell|item|macro|action, id, more?}}`). A slot holds up to 5 actions (`LAYOUT.MAX_ACTIONS`): the 1st in the slot itself (the older one-action save reads unchanged), the rest in `more = {{kind, id}, ...}`; read them with `CM.RadialSlotActions`, edit with `CM.RadialAddAction` / `SetAction` (nil entry removes) / `MakeFirstAction` (`SetSlot(nil)` clears all). `host.SetActionPips(count, current)` (`RadialBuildSlotChrome`, live wheel and editor) draws one dot per action on a slot with 2+: borderless `radial_dot.tga` tinted slate, or gold with an additive `radial_dot_glow.tga` behind the current one and the same glow art in black as a shadow behind the others (`scripts/art/make-radial-dots.py`; the canvases stay near screen size and off the pixel grid, since a bordered or larger source scaled down looked jagged), on an arc concentric with the icon, centred on the slice's outward side (`host.SetPipDirection`, set by whoever places the slot: the live view, and the editor as slices glide; dots read left to right, or top to bottom on the sides; `ACTION_PIP` in Data, fractions of the slot size; a wider radius around the larger `radial_art_` icons; on a lower-right slice the live view moves the item count to the slot's bottom left). Every mutation (`CM.RadialCreateWheel`/`SetSlot`/`AddSlice`/`RemoveSlice`...) ends in `CM.RadialRefresh`. No settings table.
- `Actions` — `CM.RadialActions`: UI shortcuts (map, bags, character...). Each is a plain `Button` `CombatModeRadialAct_<id>` running Blizzard functions; slices click it with `/click`. Function / micro-button names are checked against the live client; unverified ones fail soft. Icons: Blizzard radial icon art for the actions that have it (commands, i.e. entries with a `group`, show it as the circle slot's icon; UI panels get `def.art` → `Assets/radial/radial_art_<name>[_disabled].tga`, 128 px; `RadialEntryInfo` returns it as the 4th value and `host.SetSlotArt` in `RadialBuildSlotChrome` draws it alone, no disc/border/shadow, disabled art when unusable), Assist HUD cursor art (`Assets/atlas/cursor/crosshair_<name>_64.tga`; `CURSOR_ICON` in Actions): UI panels draw it alone via `PLAIN_ICON` (petting = Pet Journal, broom = Housing, lootall = Currency, lock = Great Vault), the Duel command (missions) shows it inside the circle slot, other actions use Interface icons, Interaction HUD cursor icons for emotes, `CM.Constants.Logo` for the options action, and the sentinel `"portrait"` (player 2D portrait) painted via `CM.RadialSetIcon` (Data) wherever an entry icon is drawn; it crops game icons (anything not under `Interface\AddOns\`) by `GAME_ICON_TRIM` per side so their bevelled square edge doesn't show inside the slot's full-size circle mask.
- `Secure` — `CombatModeRadialWheel` (SecureHandlerBaseTemplate), key button, page button and 8 slice `SecureActionButtonTemplate` children. The wheel content is copied into attributes out of combat (`rn<k>`, `rm<k>_<i>` = action count, `rt<k>_<i>_<j>`, `rv<k>_<i>_<j>`...; `rsel<i>` = the action slice i shows, reset to the 1st on every open and page turn); the key press shows the wheel, aiming is `owner:GetMousePosition()` (fractions 0..1) against per-slice direction attributes, release clicks the aimed slice and hides. While open, the wheel owner takes MOUSEWHEELUP/DOWN (by aim, decided in the secure snippet so it works in combat: on a slice with 2+ actions it cycles `rsel<i>`, re-points only that slice button (the shared `APPLY_SLICE` string; snippets can't define functions) and calls `RadialCycled` so View repaints; anywhere else it turns the page) and ESCAPE / BUTTON2 (cancel: both click the key button with "ESC", which hides the wheel, so the key's release finds it closed and does nothing; the Party Wheel does the same) as override bindings. Edits made in combat are queued (`CM.TryApplyBindingChange`) and flushed on `PLAYER_REGEN_ENABLED`.
- `View` — insecure art/labels/cooldowns as a child of the wheel (`radial_[minimal_]{bg,sel,off}_N.tga`; two looks picked by the Radial Menu Style dropdown, `global.radialStyle` "forever" (original framed art) | "minimal" (default; Blizzard's radial vignette with its ring and one 1024 background drawn 1:1 plus prerendered 512 px dividers `radial_minimal_div_N.tga`, plus the focus wedge redrawn per count as white art tinted per wheel, no `off` overlay): `CM.RadialStyle()` in Data returns the active `LAYOUT.STYLES` entry (`art` prefix, `bg` size, `dead` zone, editor `ring`, `overlay` placement); minimal art is 1:1 with ring at 84, wedge 84 to 208; slice buttons are Blizzard's gamepad circle slot, `radial_slot_{disc,border}_{normal,selected,disabled}.tga` + `radial_slot_shadow.tga`, built by `CM.RadialBuildSlotChrome` in Data and switched with `host.SetSlotState`: aimed = selected with the glow ring, unusable = disabled) plus wheel page dots under the centre text (`radial_pip_{off,active,glow,fill}.tga`, Evoker essence art on one shared canvas, untinted; one per wheel, current one active; max 5 wheels = `LAYOUT.MAX_WHEELS`, dots shrink to fit one row of `PIP_ROW_WIDTH`; each wheel has its own highlight tint, `LAYOUT.WHEEL_COLORS`). The centre's close X + red backdrop (Radial Menu) only appear once a slice has been aimed since the wheel opened (`radialLeftCentre` in View), so the freshly opened wheel shows no X. Repaints only while open; `CM.RadialViewCycled(i)` plays the aim tick and pops the icon.
- `RadialMenu` — façade: init, hooks wheel OnShow/OnHide, `RADIAL_MENU_EVENTS` (cooldowns, `SPELLS_CHANGED` re-store).

- `PartyWheel` — Party Wheel: hold a helpful spell listed in `char.partyWheelSpells` (spell-ID CSV, `SpellMultiSelect` on the Radial Menu tab) to open `CombatModePartyWheel` (own SecureHandlerBaseTemplate, 8 `type=spell` slices with fixed `unit` attributes, page button, key button `CombatModePartyWheelKey`). Keys reach it through `CM.PartyWheelPrepareKey` from `BindingOverrides` (reticle proxy path only, so keyboard keys, not Button1/2): the key button's press snippet resolves the live bar slot (`id + (actionpage-1)*12`, override/vehicle/bonus bars) → `GetActionInfo` → `pw-<spellID>` attribute (the cast name, `Name(Rank N)` when ranked, so each key casts its own rank). The list holds `CM.SpellRanks` tokens (`774` = that rank, `*774` = All Ranks of its name); `CM.PartyWheelStoreSpells` writes the listed IDs plus, for All Ranks, the matching spells on action slots 1..180, and `ApplyGroundCastKeyOverrides` runs it before re-binding the keys. Harmful-only spells are never listed (`CM.PartyWheelIsEligibleSpell` filters the picker via `spellFilter` and the stored set). One wheel at a time: each wheel holds a frame ref to the other (`radial` / `party`) and its key snippet skips while the other is shown; only the key that opened the Party Wheel resolves it. Unlisted = forward to the per-binding route button `CombatModePartyWheelRoute<idx>` (macro = the key's click-cast macro, so normal routing), listed = open; release on a slice clicks it (`CastSpellByName(name, unit)`), centre/tap clicks the centre slice `CombatModePartyWheelSelf` with macrotext set at release: `/cast [@player]` once the cursor has left the centre this hold (`pwleft`, set by the OnEnter of `CombatModePartyWheelCentre`, a protected motion-only `SecureFrameTemplate` frame the size of the dead zone: the cursor is freed already inside it, which fires no motion OnEnter, so the first return counts; a wrapped OnLeave would never run then, since Blizzard runs it only after a wrapped motion OnEnter; Mouse Look hides the cursor until the hold delay, so a tap never enters), else `/cast [@target,help,nodead][@player]` (your friendly target, e.g. an Ally Cycle pick, else you). View shows your portrait in the centre only when `CM.PartyWheelLeftCentre()`. The restricted environment has no clock, so the hold delay is insecure: the wheel frame shows on press, but `CM.PartyWheelStartReveal` (OnShow hook in the façade) only marks it open (`CM.IsPartyWheelOpen`, which drives the view and Mouse Look) after `REVEAL_DELAY`; a tap releases first and casts (centre rules) with nothing drawn. Pages (`pn`/`pu<k>_<i>`, `ptotal`) are party1..4 or raid members minus you, 8 per page, max `LAYOUT.MAX_WHEELS`, plus offline flags `po<k>_<i>` (the restricted environment has no `UnitIsConnected`; a release over an offline slice just closes, and `PartyWheelCurrent` entries carry `offline` = stored flag or live public `UnitIsConnected == false`, so View draws the slice disabled, no grow, the wedge in the class colour's luminance); rebuilt on `GROUP_ROSTER_UPDATE` / `UNIT_CONNECTION` / `SPELLS_CHANGED`, deferred silently in combat and flushed on regen (`CM.PartyWheelFlush`). View paints it through a second source (`CM.RadialViewShown("party")`): portraits via `SetPortraitTexture` in a party; in a raid (`IsInRaid`) class circle icons (`UI-Classes-Circles` + `CLASS_ICON_TCOORDS`) instead, your centre portrait too, falling back to the portrait when the class token is secret (no cooldown on them; the centre spell icon carries it; portraits and the centre spell icon get an inner black shadow, `SetInnerShadow`: `spell-glow.blp` tinted black, its opaque edge on the icon's edge, clipped by the slot's icon mask, under the cooldown), a unit plate per slot: a health ring around the portrait, drawn like the UI addon's minimap XP ring (`UI_XP/MinimapRing.lua`): back to front `radial_health_{bg,fill,ring,spark}.tga` (128 px canvases drawn at `RING_SIZE * 4 / 3`, kept near screen size and filtered a bit wide so the thin gold lines don't alias; ring textures load `TRILINEAR`, and body / border also turn pixel-grid snapping off, since a slot at rest draws them under size; `scripts/art/make-party-ring.py` sweeps the middle columns of `widgetstatusbar-bgcenter` / `fill-white` / `bordercenter` round a circle, bar top outward, `ring` = the gold border, over the fill; band middle at 27.75 px, 0.5 px per bar-art row), the fill drawn as left / right halves, each behind a `radial_health_half.tga` half-plane mask (CLAMP) rotated by `UnitHealthPercent` with a `C_CurveUtil.CreateCurve` angle curve, clockwise from the bottom. Don't switch to the XP ring's own masking (fixed masks, turning fill copies): it leaves a seam at 12 o'clock that the XP ring only hides under a tick. `UnitHealth` is always secret on Mainline / Forever (`SecretReturns`), so there the engine eases the ring: each mask's angle curve is a straight line over all of health, set with `ExponentialEaseOut` on a hidden 1 px alpha-0 StatusBar (`plate.easeBars`), whose `GetInterpolatedValue` goes into a second one (`plate.clampBars`) whose min / max hold the mask's range (so the halves move one after the other), and every frame that `GetValue` goes straight into `SetRotation` (secret all the way, never read). A new unit or a fresh open (`plate.easedUnit` nil) snaps; the spark's alpha curve and the fill colour follow the current health. Public health (older clients) is drawn by plain Lua math instead and eased every frame toward the latest reading (repainted on that unit's `UNIT_HEALTH` / `UNIT_MAXHEALTH`, registered on the view only while the real Party Wheel is open, plus the 0.2 s loop for range / dead) (`plate.goalPct` / `shownPct`, `RING_EASE_SPEED`, like the Ally HUD bar's ExponentialEaseOut; a new unit or a fresh open starts on it). `Texture:SetRotation` takes secrets from addon code; `Cooldown:SetCooldown` / `SetCooldownFromDurationObject` only from untainted code, so no swipe. A mask (256 px, hard edge) edge lying on a half's own edge (the centre line at 12 o'clock) fades that column into a faint line, so the left mask turns `RING_TOP_OVERSHOOT` past 12 o'clock and the right one stops that short of 0: only the halves' crisp texture edges meet at the top, and the sliver this costs sits at 6 o'clock under the role icon. Never patch over the line: the plate's range alpha is applied per texture, so any overlapping texture shows as a brighter block on out-of-range members. The fill is the status bar's shaded white, tinted by `CM.AllyCycleHealthBar.GetFillColor`; `radial_health_spark.tga` (ADD: `widgetstatusbar-spark` standing across the band's bottom, 23 bar rows tall as on the XP ring, centred on the band) marks the fill's edge: rotated by a 0 → -2pi curve, alpha from a curve that drops to 0 within `RING_SPARK_EDGE` of empty / full; the ring is the portrait's border: unit slots call `host.SetSlotRing(RING_ICON, RING_SIZE)` (Data: no shadow / border, icon fills the opening over the normal disc art sized to it (so the selected glow can't show through the portrait's soft edge), only the selected glow sized to the ring; the plate sits above the chrome's `over` frame so the glow is behind it); `RING_SIZE * 4 / 3` stays a whole even number for pixel-exact halves), the role icon on the ring's bottom notch and the class-coloured name from `CM.AllyCycleTarget.GetDisplayName` under it, greyed when dead and replaced with "Dead" / "Offline" (`DEAD` / `PLAYER_OFFLINE`, offline wins; `plate.displayName` restores it); offline members (`CM.AllyCycleTarget.IsOffline`: a public `UnitIsConnected == false`, checked with the health) are desaturated like the Ally HUD: portrait, ring, role desaturated, name grey, the fill in `HealthBar.GetDeadColor()` desaturated with no spark; Ally HUD parity (refreshed with the health): the low-HP glow (`plate.lowGlow`, the slot's `border_selected` art desaturated, ADD, at `LOW_GLOW_SIZE` behind the ring, tinted by `CM.AllyCycleHealthBar.GetGlowColor` whose alpha may be secret (vertex colour only), pulsed through its holder frame's `SetAlpha` (`plate.lowGlowFrame`; a texture's `SetAlpha` is its vertex alpha, so pulsing the texture itself wipes the curve's 0 and lights every member) by `StepLowGlows` with `GlowPulseAlpha` / `GetGlowPeriod`; hidden when dead / offline), the raid marker on the ring's top (`plate.marker`, `Target.ApplyRaidMarker`, desaturated when grey); no threat indicator (the Ally HUD has none either; a ring tint from `UnitThreatSituation` was tried and dropped, it never showed on live members); portrait + plate dimmed out of range (`Target.GetRangeAlpha`, alpha may be secret, refreshed with the health); names are first name only; the aimed wedge is tinted with the member's class colour), no centre texts or close X: the centre is a circle slot with the spell's icon + cooldown plus the Assist HUD's effects (`centerFx`: `spell-glow.blp` inner glow breathing via `CM.AssistedHighlightMotion.GlowBreathAlpha`, and the `PROC_ATLAS` FlipBook built with `Motion.ApplyProcFlipSettings`, played once in reverse each time the spell icon appears (open, spell change, cursor leaving the centre); glow tinted the Assist cyan `Motion.ASSIST_COLOR_*`, sized to the visible icon in the Assist HUD's proportions (`CENTRE_FX_GLOW_PER_VISIBLE`: the bright rim just outside the visible icon, unmasked); FlipBook untinted, sized by `CENTRE_FX_PROC_FILL` so the slash covers the slot's border, tuned by eye in game), swapped for your portrait in the same unit plate (`PaintUnitPlate(centerSlot, "player")`: health ring, role, name) while the cursor rests there (animated by `SetCenterAim` / `StepCenterSwap`: the slot shrinks to `CENTRE_SWAP_SCALE` and fades out, swaps at the midpoint and grows back in over `CENTRE_SWAP_DURATION`; instant on open; reversing mid-swap turns around from where it is), over the same centre backdrop that turns red on the Radial Menu, tinted with your dimmed class colour instead, crossfading from `SPELL_BACKDROP` green behind the spell icon (`ApplyCenter`) (page dots sit at `pipY` under the spell icon and drop to `pipPlateY` under your plate).

Mouse Look handoff: `CM.IsRadialMenuOpen` (true for either wheel) feeds `CM.ShouldFreeLookBeOff`; hiding the wheel re-locks through `CM.ReconcileFreeLook`.

Forever supports secure snippets, so there is no client gate. Cooldown values are secret on Mainline: pass them straight to the Cooldown widget inside `pcall`, never compare. UI: `UI/Options/Tabs/TabRadialMenu.lua` only (no separate window): a custom row drawing the wheel with 8 pooled slice buttons (each shows one of its actions, `shownAction[slot]`, editor-only; the mouse wheel steps through them and is enabled only while a 2+ action slice is hovered, so the tab still scrolls; click = searchable dropdown of UI actions / emotes that replaces the shown one (titled "Replace X"), with Make First / Remove Action / Clear Slice; a filled slice with room has a "+" badge on its side facing the wheel's centre, opposite the dots (`BuildAddBadge`; no mouse of its own, the wheel's `hit` frame asks `IsMouseOver`) opening the same dropdown in add mode; drop spell/item/toy/mount/macro (on the slice or its +) = set an empty slice or append to a filled one, a full one leaves it on the cursor; right-click = remove the shown action, or the slice when it has one or none, never the last slice, left-drag a slice around the wheel = it trades places with its neighbours, wrapping at the ends, committed via `CM.RadialReorderSlots`), the wheel title on top (click to rename, `CM.RadialRenameWheel`) with page arrows either side and one pip per wheel below it (click selects, left-drag reorders the wheels via `CM.RadialMoveWheel`), an accent "Add Slice" slice drawn on the wheel in the next free position, and a centre disc split in two halves (red "-" removes the wheel, green "+" opens a menu of the presets + Blank Wheel). A wheel stores an optional `name` (default "Wheel k") and `count` slices (editor positions); empty ones are skipped by the live wheel. There is no enable toggle (unbound key = off) and no dead-zone option (the style's `dead`); the appearance options are the Radial Menu Style dropdown and the Radial Menu Scale slider (`global.radialScale`, 0.5-1.5, `CM.RadialScale`). Both setters re-store **both** live wheels (`CM.RadialRefresh` + `CM.PartyWheelRefresh(false)`; the dead zone and scale live on each secure frame). Each `StoreImpl` calls `Wheel:SetScale` out of combat; the art, slices and Party Wheel centre zone are children, and aiming (secure and insecure) already works in the wheel's own units, but `SetPoint` offsets do too, so the stored `ryoff` is `crosshairY / scale`. The editor on the tab doesn't scale.

**In-game checks:** slices with several actions (cycle and release in and out of combat: spell, item, macro, UI action; centre and one-action slices still turn pages; cycling works with one wheel; a reopen starts on the 1st; one wheel notch = one step; ESC / right-click still cancel; dots readable at 8 slices, both styles, scale 0.5 and 1.5; the options tab still scrolls except over a multi-action slice; editor add / drop / Make First / remove survive `/reload`).

**In-game checks (Party Wheel):** party and raid (pages, mouse wheel, class circles), in combat (roster changes apply after combat, druid form swap follows the live bar), offline / dead / out-of-range members, a tap vs a hold on the centre (Ally Cycle pick vs you), ESC / right-click cancel casts nothing, only one wheel at a time, an unlisted spell on a routed key still casts, and on Forever / Classic a lower-rank key casts that rank (slice, centre, tap), All Ranks covers different ranks on different keys, and a rank trained or dragged to a bar works without a reload.

## PartyWheel.lua notes

- Out of combat only: the allowlist (pw-<spellID>), the pages of unit tokens (pn<k>, pu<k>_<i>: party1..4, or raidN minus the player, 8 per page, max LAYOUT.MAX_WHEELS pages), offline flags (po<k>_<i>: the restricted environment has no UnitIsConnected; a release over an offline slice just closes) and the slice directions. Roster / list / connection changes in combat wait for CM.PartyWheelFlush (regen); the view desaturates offline members live meanwhile.
- Hold delay (insecure: the restricted environment has no clock): the secure wheel opens on press, but CM.PartyWheelStartReveal only reports it open (CM.IsPartyWheelOpen, so the view and Mouse Look react) after REVEAL_DELAY; a release before that just casts.
- Centre target: the dead zone is a protected motion-only frame (CombatModePartyWheelCentre) whose OnEnter (the cursor coming back) sets pwleft; a centre release then casts "/cast [@player]", else (tap, or never left) "/cast [@target,help,nodead][@player]" through the centre slice.

## View.lua notes

- Ally HUD parity: out-of-range members dimmed (AllyCycleTarget.GetRangeAlpha), the low-HP pulsing glow (AllyCycleHealthBar.GetGlowColor / GlowPulseAlpha; alpha may be secret), offline members desaturated and unselectable. The aimed wedge takes the member's class colour.
- The Party Wheel centre is a circle slot with the spell's icon + cooldown and the Assist HUD's breathing glow and proc FlipBook (AssistedHighlightMotion), swapped (SetCenterAim) for your own unit plate while the cursor rests there (it casts, so no cancel X).
